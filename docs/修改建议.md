## 一、一定要完善的地方（P0，不做会扣分）

### 1. 没有 Git、CI、覆盖率，也没有“干净仓库”

我实测当前目录：**14,302 个文件、480 MB**（含 `.venv/.uv-cache/.browsers`）；真正要提交的 `src/tests/scripts/eval/docs` 只有约 **3 MB**；`reports/` 有 **1,235 个文件、33 MB**。而且当前目录**没有 `.git`、没有 `.github/workflows`、没有 coverage 配置**。

这是面试包装的第一硬伤：面试官打不开一个 480 MB 的压缩包，也看不到提交历史。

最小修复：

powershell



```
cd C:\Users\ysy\Desktop\备选项目\agentscope-deep-researcher
git init
# .gitignore 已含 .env/.venv/reports，确认不要提交它们
git add src tests scripts eval docs README.md pyproject.toml uv.lock LICENSE start.bat
git commit -m "feat: evidence-first research agent with reproducible evaluation"
```

加一个 `.github/workflows/ci.yml`：`ruff check` + `python -m unittest discover -s tests` + `python scripts/verify_offline.py --run-offline`；再加 coverage（`coverage run -m unittest`）。**CI 绿 + 覆盖率报告**比再写 10 页文档更有说服力。

### 2. 没有一页入口，文档过载

根目录 9 份中文长文 + 2,500 行面试手册 + 1,200 多个 reports 文件，第一印象是“资料很多，但不知道从哪看”。面试官只会给你 3–5 分钟。

加一个 `PORTFOLIO.md`，只放六块：

1. 30 秒项目介绍；
2. 一张架构图（模型 → 工具 → Session → 证据 → 评测）；
3. 一个 headline 结果（n、指标、区间/边界、失败分类）；
4. 一个负结果与你的决策；
5. 3 分钟 demo 链接/GIF；
6. 已知限制与下一步。

把旧文档移到 `docs/archive/` 或保留但不在首页展开。**文档不是越多越好，首页必须能在 3 分钟内读完。**

### 3. 结果太碎，没有一个“能记住的数字”

现在有 style-pair、selector-pair、revision、web、tool-focus 多组结果，但分散在 reports 里。面试官记不住“很多实验”，只记得“一个表 + 一个结论”。

建议做一次 **headline experiment**：

- 10 题 × 2 策略 × 2 次 = 40 trials（正好在 40 上限内）；
- 先写 `protocol.json` 冻结题、标准、预算、变量、停止规则；
- 报告：`passed/failed/unassessed`、`success_rate_bounds` 或 Wilson 区间、按 L1–L5 的失败分布、token/耗时；
- 选一个正结果 + 一个负结果，明确“这次只证明了什么”。

例如：

> “在 10 题冻结网页上，`balanced` 把长度门槛从 0/10 提到 6/10，但语义通过数没有显著变化；所以我保留 `segments` 为默认，只把 `balanced` 作为多关注点选项。”

这比“我做了很多优化”强十倍。

### 4. 评测效度：没有 holdout、没有真实人工

当前 20 题是开发集（`eval/research_suite.json`，20 题/62 条标准/42 条 required），复核多是 assistant，盲评 52 条全 pending。面试官会问：“你的分数是真的吗？”

最小可行修复（不需要大成本）：

- 另写 **10 道未见题**（同一批文档、同一格式），跑完之前不改标准；
- 找 **2 位同学**独立盲评（用 `blind-prepare` 导出模板），算 Cohen's κ；
- 报告里分“dev / holdout”两栏，明确“assistant 标签不是 gold”。

10 道题 + 2 个人，足以把“自说自话”变成“有校准的评测”。

### 5. 包名/仓库名带 “interview”

`pyproject.toml` 的 distribution name 是 `agentscope-deep-researcher-interview`。面试官看到 “interview” 会下意识觉得这是“面试练习题”，而不是“产品/研究项目”。

最低成本：仓库名和 README 标题改成 `evidence-researcher` 或 `as-researcher`；包名可保留（有 13 处 `importlib.metadata.version(...)` 引用，改名要同步改 benchmark_research.py 等脚本）。**仓库名/标题优先，包名可选。**

### 6. “是不是 AgentScope wrapper” 的质疑

这是大厂面试最可能的一刀。准备三个“只有你做了”的决定，并能打开代码：

1. 为什么把预算放在 `ResearchSession` 而不是提示词里；
2. 为什么 `@snippet` 和 `@page` 必须分层，为什么 `read_page` 只能读已登记的 `SRC`；
3. 为什么一次 `search_error` 就终止搜索阶段，而不是自动重试。

再准备一个“坏输入 → 旧行为 → 新行为 → 回归测试”的故事（例如 `staged_sources` 原子提交、`template` 载荷被当正文、重复标题前缀挤占预算）。**能讲清一个 bug 的前后对比，比列 20 个功能更能证明 ownership。**

### P1（加分，不致命）

- **服务化/规模**：FastAPI `POST /runs` + `GET /runs/{id}` + 后台 worker + SQLite/Redis 队列 + Docker Compose；支持断点续跑、幂等、限流；20 并发 + p95。这是大厂后端最认的信号。

## 二、增加闪光点的方向（按 ROI 排序）

| 方向                         | 做什么                                                       | 量化指标                                            | 适合岗位            | 成本   |
| ---------------------------- | ------------------------------------------------------------ | --------------------------------------------------- | ------------------- | ------ |
| **1. 可复现 Agent 评测装置** | 30–50 题、3 模型 × 3 策略、一条命令跑完、报告含区间/失败分类/成本；可加一个小型 leaderboard | 10 分钟内复现；3×3×20 的批次；每个失败有 L1–L5 标签 | 所有 AI 应用/平台岗 | 2–3 周 |
| **2. Claim-level verifier**  | 对每句回答做“引用是否存在 + 摘录是否支持”的确定性检查，可选小 NLI/LLM judge；与 100 条人工标签比 precision/recall | 抓出 X% 无支持句，误报 Y%；κ                        | 算法/评测/安全      | 2–3 周 |
| **3. 持久化执行/服务化**     | 队列、断点续跑、幂等、限流、可观测性；kill worker 后能恢复   | 20 并发、p95、崩溃恢复 0 丢任务                     | 后端/基础设施       | 2 周   |
| **4. 检索/选段改进**         | BM25 + embedding reranker，或 query decomposition；预注册的单变量 A/B | 在 frozen 语料上 coverage/support 的提升 + 区间     | 算法/研究           | 2–3 周 |
| **5. 安全/Trust & Safety**   | 浏览器 `--network none`、SSRF/DNS rebinding 测试、真实注入语料 | 攻击用例通过率、0 宿主影响                          | 安全/风控           | 1–2 周 |
| **6. 产品化 Demo**           | 最小 Web UI：问题、回答、引用悬停看证据、trace 时间线、成本/延迟 | 3 分钟视频、5 个用户试用反馈                        | 产品/LLM 应用       | 1 周   |

**推荐组合（不要全做）：**

- 中厂 AI 应用：**1 + 6**；
- 大厂 AI 平台/应用：**1 + 3**（或 1 + 2）；
- 大厂后端：**3 + 1**；
- 安全岗：**5 + 1**；
- 研究/算法：**2 + 4 + holdout**。

其中 **1 的性价比最高**：它把你现在最强的“评测严谨”变成可展示的产品，而且很少有本科生会做“评测基础设施”。**不要**为了关键词去加多 Agent、向量库、微调；这些会引入你答不上来的追问，还会稀释“证据优先”的主线。

## 四、面试怎么讲（三段故事 + 五个必答）

### 30 秒版

> “我做的是一个证据优先的研究 Agent 和有边界的评测装置：模型只能通过两个只读工具取证，应用控制预算、去重、来源资格和引用层次；每次运行保存 trace、完成原因和证据，能用冻结网页复现。我用它做过 A/B，发现 compact 只改善长度合规、不改善语义正确，所以默认没有开启。”

比“我用了 AgentScope 做 deep research”强，因为包含：问题、约束、证据、负结果、决策。

### 三个故事

1. **设计取舍**：预算为什么在 Session 不在提示；`@snippet`/`@page` 为什么必须分层；为什么一次 `search_error` 就停。
2. **调试**：`staged_sources` 原子提交（坏搜索不再留下半条证据）；或 template 载荷被当正文；或重复标题前缀挤占预算。要有 trace、前后对比、回归测试。
3. **评测**：`compact` 长度 3/8→6/8 但语义 6/8；`selector` 0→3 但语义不变；所以“默认不开”。这是“negative result 阻止了错误默认”的成熟故事。

### 五个必答

- “这不就是 AgentScope wrapper 吗？” → 三个决定 + 代码 + 一个 bug 修复。
- “为什么不用 LangGraph/向量库/多 Agent？” → 当前失败在选段/表达，不在框架；加东西会增加调用/权限/评测成本。
- “准确率多少？” → 没有单一准确率；给 n、rubric 通过数、三态、区间；不把开发集叫 gold。
- “1000 QPS 怎么办？” → 无状态 API、队列、worker pool、限流、缓存、对象存储；当前是批量原型，给出演进路径。
- “你个人做了什么？” → 如实说 AI 协助，然后用 diff、测试、反例证明理解。

### 不要做

- 不要为关键词加多 Agent/向量库/微调；
- 不要再扩写文档；
- 不要声称 production、human gold、SOTA、完整 RAG、多 Agent；
- 不要隐藏负结果——它是你最强的可信度来源。
