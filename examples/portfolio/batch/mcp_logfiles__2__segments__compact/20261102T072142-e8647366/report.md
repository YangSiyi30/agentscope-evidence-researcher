## 保存的回答

> 以下原样展示run.answer；它可能是模型回答、已采用的缩稿候选，或未完成运行的程序提示。原稿与候选见revision记录。

不能推出“禁止服务端写任何日志文件”。规范（2025-11-25 transports）限制的对象是 stdio 三个流中 stdout 和 stdin 两份通道的内容：stdout 只能承载有效 MCP 消息，服务端不得向 stdout 写任何非 MCP 消息的内容；客户端不得向服务端 stdin 写非 MCP 消息内容 [SRC-937FAE64@page]。至于日志，规范明确允许（MAY）服务端向 stderr 写 UTF-8 字符串，用于信息、调试和错误日志；客户端可捕获、转发或忽略 stderr，且不应假定 stderr 输出就代表错误 [SRC-937FAE64@page]。

日志文件不在上述限制范围内：规范既未禁止写文件，也未规定文件日志的内容。但这里只是“未禁止”，并不等于“允许”：本次读取的是页面片段，并非全文 [SRC-937FAE64@page]，因此其他章节或本规范之外的政策是否另有要求，尚不清楚。
