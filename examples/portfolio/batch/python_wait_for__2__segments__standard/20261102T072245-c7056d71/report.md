**返回值时机**：超时发生时，`wait_for` 会取消 `aw`，并抛出 `TimeoutError`。不过，它并不是一超时就立即返回，而是会等到该 future 真正被取消之后才返回；因此总等待时间可能超过 `timeout`。如果取消过程中发生异常，该异常会被向外传播。另外，如果等待本身被取消，`aw` 也会被取消。[SRC-4385BCC3@page]

**设置1秒并不保证总等待不超过1秒**：文档已经明确说明总等待可能超出设定的超时值。自 3.7 起，`wait_for` 会等待被取消的 awaitable 完成取消；而更早的版本会立刻抛出 `TimeoutError`。本次查看的 3.13 文档中，该条目注明，3.12 起改用 `asyncio.timeout()` 实现，并且当 timeout 为正数时，协程不再被包装为 Task。文档中“等待至多1秒”的示例预期输出为 `timeout!`；但这只是示例，不能据此推断总时长严格有界。[SRC-4385BCC3@page]

**局限**：只读取了有限正文片段，未查看 `shield()`、`asyncio.timeout()` 的完整说明；对于超时后取消拖长的具体上限、以及被取消协程吞掉 `CancelledError` 时的行为，本次证据不足。
