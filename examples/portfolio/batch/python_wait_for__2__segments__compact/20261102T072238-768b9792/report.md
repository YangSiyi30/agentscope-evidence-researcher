## 保存的回答

> 以下原样展示run.answer；它可能是模型回答、已采用的缩稿候选，或未完成运行的程序提示。原稿与候选见revision记录。

Python 3.13 文档说明：发生超时时，`wait_for` 会取消 `aw`，并等待它**真正被取消**之后才抛出 `TimeoutError`；因此总等待时间可能超过 `timeout` [SRC-4385BCC3@page]。3.7 起改为：因超时取消 `aw` 时，需等 `aw` 取消完成，而不再立即抛出 `TimeoutError`；取消过程中产生的异常会被传播 [SRC-4385BCC3@page]。

当等待本身被取消时，`aw` 也会被取消 [SRC-4385BCC3@page]。

所以设置 `timeout=1.0` **不保证**总等待不超过 1 秒；只有当被等待对象能迅速响应取消时，总等待才约等于 1 秒 [SRC-4385BCC3@page]。例如，若 `aw` 吞掉 `CancelledError`，取消可能被拖延（取消语义段落 [SRC-4385BCC3@page]）。3.12 起，如果 `aw` 是协程且 `timeout` 为正，就不再把它包装成 Task [SRC-4385BCC3@page]；这对取消传播的具体影响，本次片段未详述，未见文档明示。
